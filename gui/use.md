## 一、运行 UI 程序

> 在项目根目录 `/home/ubuntu22/stm32/ANO_LX_FC` 下执行（虚拟环境 `.venv-linux` 已建好，直接用）。

### 连真飞控（正常使用）

插上 USB 数传，运行：

```bash
DISPLAY=:1 ./.venv-linux/bin/python -m gui.main
```

界面打开后，在顶部**连接栏**选串口号 → 点「连接」即可收到飞控数据。

### 没有飞控时（仅验证界面能开）

```bash
DISPLAY=:1 LINGXIAO_GUI_FAKE=1 ./.venv-linux/bin/python -m gui.main
```

> ⚠️ 离线仿真（FakeWorker）**不发 IMU 原始帧（0x01）和四元数姿态帧（0x04）**，所以 IMU 测试台里的数值/曲线/3D **不会动**。此模式只用来确认界面本身能正常启动。

### 打开 IMU 测试台

顶部菜单栏 → **功能(U)** → 勾选 **「IMU 测试台」**（再次取消勾选切回主界面，切换不断流）。

## 二、IMU 数据质量测试台功能详解

这个测试台是为了给 **IMU 数据做体检**：看数据流正不正常、加速度/陀螺准不准、姿态稳不稳，为后续的 EKF/UKF 融合定位打基础。顶部有 5 个页签，从左到右逐个说明。

### 数据从哪来

飞控通过 USB 数传，用**匿名协议 V7** 发来一帧帧数据。测试台关心其中三种帧：

| 帧 ID | 名字 | 内容 | 大概频率 |
|:---:|---|---|:---:|
| `0x01` | IMU 原始 | 加速度 XYZ + 角速度 XYZ + 震动标志 | ~100 Hz |
| `0x04` | 四元数姿态 | 四元数 → 换算成 Roll/Pitch/Yaw | ~67 Hz |
| `0x07` | 飞行速度 | 三轴速度 | ~50 Hz |

程序内部有个"数据中枢"负责把原始字节解码成物理量（m/s²、rad/s、角度），再分发给各个页签。**你只需要看界面，不用关心解码细节。**

### Tab 1 · 实时总览

> **一句话**：一眼看清"数据流健不健康 + 当前各物理量数值 + 飞机当前姿态"。

**布局**：左上=帧率表，左下=数值表，右侧=3D 姿态。

#### ① 帧率表（左上）

| 列 | 含义 |
|---|---|
| 帧类型 / 帧ID | 是哪种数据帧 |
| 频率(Hz) | 每秒收到多少帧（2 秒滑动窗口实时算） |
| 累计 | 开机到现在总共收到多少帧 |
| 状态 | 🟢**达标** / 🟠**偏低** / ⚪**掉线** |

**怎么看**：
- 绿色"达标" = 该帧频率正常（≥ 期望值的 80%）。
- 橙色"偏低" = 收到了但频率不够，可能是数传带宽不足或飞控负载高。
- 灰色"掉线" = 超过 1.5 秒没收到这种帧，频率显示"--"。

**怎么理解**：正常连接时三行都应是绿色"达标"。如果某行变灰，说明那种数据断了，先查连接和飞控配置。

#### ② 数值表（左下）

实时显示每个物理量的**数值 + 单位 + 原始 LSB 值**：

- 加速度 acc_x/y/z（m/s²）、加速度模长 |a|
- 角速度 gyr_x/y/z（rad/s，括号里附带 °/s 便于直观理解）
- 姿态角 roll / pitch / yaw（°）
- 震动标志 shock

**怎么看**：
- 平放静止时，**|a| 应约等于 9.8**（一个重力），acc_z 约 9.8、acc_x/y 约 0。
- 静止时三个角速度都应接近 0。
- "原始(LSB)"列是飞控传来的整数原始值，主要给调试/校准时对照用。

#### ③ 3D 姿态（右侧）

一个蓝色扁盒子代表飞机，**红色锥体是机头方向**。盒子会跟着飞控实时姿态转动。顶部青色文字实时显示 `Roll / Pitch / Yaw`。

**怎么看**：
- 把飞控拿在手里转，盒子应跟着同步转，机头（红锥）指向应与实物一致。
- 世界坐标的网格和三色参考轴是固定不动的"地面"，方便对照盒子转了多少。

**怎么理解**：这是姿态解算是否正常的最直观检查。如果盒子乱跳或转向相反，说明四元数解算或坐标约定有问题（真机上需要重点核对 yaw 方向）。

### Tab 2 · 曲线监控

> **一句话**：把加速度、角速度画成随时间滚动的波形，看噪声、看抖动、看有没有毛刺。

- **上图**：加速度三轴曲线（m/s²），X=红、Y=绿、Z=蓝。
- **下图**：角速度三轴曲线（rad/s），同样 X 红 / Y 绿 / Z 蓝。
- 横轴是时间（约 10 秒滑动窗口），两图时间轴联动。

**怎么看**：
- 静止时：加速度 Z 应是一条约 9.8 的平线，X/Y 约 0；角速度三条都贴近 0。
- 运动时：曲线跟着动作起伏。
- 看**毛刺/尖峰**：如果曲线时不时窜出孤立尖峰，说明数据有跳变（噪声或丢包）。
- 看**噪声粗细**：线越"毛"噪声越大，越"细"越干净。

**怎么理解**：这是判断传感器数据"干不干净"的窗口。融合算法对噪声和毛刺很敏感，这里能提前发现问题。

### Tab 3 · Yaw 跟随

> **一句话**：专门测"转一个角度松手后，航向角会不会回弹、回弹多少"，评估 Yaw 的跟随与稳定性。

这是你专门要的自定义测试。**使用步骤**：

1. 点 **「装填测试」**（进入等待状态）。
2. 手动把飞控绕 Z 轴（航向）转一个角度，然后**松手停住**。
3. 程序自动识别：开始转 → 转动中 → 你停手 → 等它稳定 → 出结果。

**状态机 5 个阶段**：未装填 → 等待旋转 → 旋转中 → 停手稳定中 → 完成。

**怎么看**（底部 8 个指标）：

| 指标 | 含义 |
|---|---|
| 状态 | 当前处于哪个阶段 |
| 当前 yaw | 实时航向角 |
| 起始 yaw | 开始转动时的角度（作为 0 基准） |
| 峰值 yaw | 你**松手那一刻**转到的最大角度 |
| 稳定 yaw | 最终**稳定下来**的角度 |
| 回弹量 | 峰值 − 稳定（松手后往回弹了多少度） |
| 回弹百分比 | 回弹量 ÷ 峰值 |
| 稳定耗时 | 从松手到稳定用了多久 |

上方曲线画的是 **yaw 随时间变化**（相对起始角）：蓝色区间=旋转段，橙色区间=停手稳定段，红色虚线=峰值，绿色虚线=稳定值。

**怎么理解**：
- 回弹量/回弹百分比越小越好，说明航向稳、不漂。
- 它用**物理角速度 gyr_z**（松手后≈0）判断你"手停了没"，再用 **yaw 自身是否稳定**判断"数据漂没漂"——正好抓住"手已停但数据还在漂"这种问题。
- **「导出曲线CSV」** 可把整段 yaw-时间数据存成 CSV，方便离线分析。

### Tab 4 · 静态校准

> **一句话**：设备静止放好，采一段数据，算出应该填的**加速度尺度**和**陀螺零偏**，一键复制成配置片段。

分上下两块。

#### ① 加速度尺度校准（上）

**前提**：设备**水平静置，Z 轴朝上**（机顶朝天）。

**步骤**：点「开始采样」→ 静置几秒 → 点「停止采样」。

**怎么看**：
- "实测 acc_z"应该是 9.8 附近；如果偏低（比如只有 6.4），说明当前 `acc_scale` 不对。
- 程序自动算出 **建议 acc_scale**（原理：新值 = 当前值 × 9.80665 ÷ 实测均值）。
- 下方生成一段 **yaml 片段**，点「复制 yaml 片段」直接粘到配置文件。

#### ② 陀螺零偏校准 + 90° 积分自检（下）

**零偏**：设备**静止不动**，点「开始静置采样」→ 几秒后「停止」。
- 静止时陀螺理论上应输出 0，实际会有个小偏置，这个偏置就是"零偏"。
- 程序算出三轴零偏均值（目标每轴 |值| < 0.005 rad/s），达标显示 ✓，超标显示 ✗，并生成 yaml。

**90° 积分自检**：验证陀螺**尺度准不准**。
- 点「开始积分」→ 手动把设备**匀速转 90°** → 点「停止积分」。
- 程序把角速度对时间积分，理论结果应是 **90°±2°**。达标 ✓，否则 ✗ 并显示偏差。

**怎么理解**：
- 加速度尺度保证"1g 就是 9.8"，陀螺零偏保证"静止时不乱转"，积分自检保证"转 90° 算出来就是 90°"。三者是 IMU 能不能用的基础。
- 校准结果**不会自动写进飞控**，只生成文本让你手动复制，安全可控。

### Tab 5 · 质量报告

> **一句话**：点一下"开始检测"，采一段数据，自动出一张"体检报告"，10 项逐条打勾。

**步骤**：点「开始检测」→ 采集一段（**静态项目需设备静止**）→ 点「停止并评估」→ 看清单表。

**报告的 10 项检查**：

| # | 检查项 | 判据 |
|:--:|---|---|
| 1 | 数据完整性 | 无 NaN / Inf |
| 2 | IMU 采样频率 | ≥ 50 Hz |
| 3 | 姿态采样频率 | ≥ 50 Hz |
| 4 | 加速度量程 | ≤ 156.8 m/s² |
| 5 | 角速度量程 | ≤ 34.9 rad/s |
| 6 | 加速度静态噪声 | std < 0.05 |
| 7 | 角速度静态噪声 | std < 0.01 |
| 8 | 四元数模长 | 0.999 ~ 1.001 |
| 9 | 姿态静态漂移 | Roll/Pitch < 2°，Yaw < 3° |
| 10 | 姿态无跳变 | 相邻帧 < 5° |

**怎么看**：
- 每行给出「实测值 / 判据 / 结果」，🟢通过 / 🔴不通过 / ⚪跳过（该项没采到数据）。
- 顶部有**总结论**：全部通过（绿）或"N 项不通过"（红）。

**怎么理解**：
- 第 6/7/9/10 项是**静态项**，**必须设备静止时采集**才有意义——如果你在动，这些"不通过"是正常的。
- 四元数模长应非常接近 1，偏差大说明姿态解算异常。
- 这张报告是"这批 IMU 数据能不能喂给融合算法"的快速结论。

## 三、常见问题

**Q：界面打开了，但 IMU 测试台里数值/曲线/3D 都不动？**
A：多半是用了 `LINGXIAO_GUI_FAKE=1` 离线模式（它不发 0x01/0x04）。请连**真飞控**并用方式 A 启动；同时确认顶部连接栏已成功连上串口。

**Q：3D 姿态盒子不显示，只有一行提示文字？**
A：缺 `pyqtgraph` 或 `PyOpenGL`，或者没有真实桌面。重新执行第 3 步安装依赖，并确保用 `DISPLAY=:1` 启动。

**Q：3D 盒子会转，但方向和实物相反？**
A：这是坐标/符号约定问题（尤其 yaw 方向）。属于真机联调阶段要确认的点，界面本身没坏。

**Q：帧率表某行变灰"掉线"？**
A：那种数据帧超过 1.5 秒没来。检查数传连接、飞控是否在发该帧、以及带宽是否被占满。

**Q：校准/质检要采多久？**
A：静态类采集**静止保持 3~5 秒**即可，采样越久统计越稳。
