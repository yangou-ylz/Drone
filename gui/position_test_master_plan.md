# 位置测试功能（Position Test）总体规划

> 2026-07-19 注意：本文是旧的 IMU 测试台内“位置测试面板”规划，目标是比较 0x07/0x01/0x32 等位置估计算法。
> 当前新增的主菜单独立“位置测试”页面用于树莓派 `0xF5` 数据的 STM32 下行镜像 `0xF6` 调试，代码在
> `gui/position_test/position_test_window.py`。两者不是同一个功能，不要把本文的“不碰 STM32 C 代码”误套到
> `0xF6` 镜像阶段。

> 目标：在 GUI（`/gui`，**不碰 STM32 C 代码**）里做一个高度抽象、可扩展、易维护的
> 位置调试功能。先在上位机验证各种"由观测量得到位置"的算法，效果好的再移植到飞控。
> 创建日期：2026-07-17

---

## 一、功能需求（来自用户）

1. 底层：一个**高度抽象**的位置估计器体系，接口丰富统一，支持多种"位置来源"：
   - 直接接入外部传感器观测位置（转发，0x08 / 0x32 帧）
   - 速度积分（0x07 速度帧 → 位置）
   - 加速度二次积分（0x01 IMU 帧 → 位置）
   - 未来：滤波、融合（互补滤波、卡尔曼等）
   - 通过**传参 / 改模式**切换底层位置计算方式
2. 算法都遵循**统一抽象接口**，可统一注册、管理、扩展。
   接入新算法后启动 GUI 即刻生效，把观测量处理成位置并显示。
3. GUI 排版：
   - X / Y / Z **各自一个独立图**（不合并），三块长方体区域相互隔开
   - 每个图**下方**对齐显示该轴实时**位移**数值
   - **检测的是位移（相对量），不是绝对位置**
   - 统一「装填」按钮：点击后开始计算一个时间阈值内的相对位移，分显示在三图
   - 「清除/重置」功能
   - 可在界面调判据参数（保持时长、稳定窗口等，参考姿态/线速度面板但不照搬）
   - CSV 导出
   - 其它便于调试底层算法的功能（见待定项）

## 二、约束

- 代码只写在 `/gui`，纯 Python + PySide6 + pyqtgraph，复用 `ImuDataHub` 信号
- 与现有 `velocity_test_panel.py` / `yaw_test_panel.py` 风格一致，但功能不照搬
- 数据源：`ImuDataHub` 的 `velocity`(0x07) / `imu_raw`(0x01) / 位置帧(0x08/0x32) 信号

## 三、待用户确认的关键决策（见下方"方案征询"）

- [ ] 单算法激活 vs 多算法并行对比
- [ ] 三轴坐标系轴向映射确认

## 四、进度

- 2026-07-17：需求整理，架构方案待用户拍板（本文件）。
- 2026-07-20：主菜单独立“位置测试”页面进入树莓派对接调试阶段。已确认：树莓派只运行 ROS 导航/SLAM 不会自动发送 `0xF5`；必须额外运行测试发送程序（如 `send_slam_cur_f5.py`）才会向 STM32 发当前位置。该设计是安全解耦：导航建图、测试发送、飞控解析、GUI显示分开验收，避免联调期误触发控制。
- 2026-07-20：`0xF5 -> STM32 -> 0xF6 -> 数传 -> GUI` 原始数据链路已验收。用户运行测试发送程序后，GUI 可以看到原始解析数据；此前“等待 0xF6”的主要原因是未运行发送程序，不是烧录失败，也不是 IMU/数传不能转发自定义帧。后续从 GUI 功能主线继续：坐标标定、稳定性测试、轨迹回放和调试诊断。
