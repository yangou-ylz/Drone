# 凌霄飞控代码审查

## 步骤
1. 读取被审查的文件/函数内容
2. 加载项目规范：`.github/instructions/drone-c-conventions.instructions.md`
3. 逐条对照下方检查清单
4. 列出所有不符合项，并给出**具体修正建议**

---

## 审查清单

### ? 命名规范
- [ ] 全局变量使用模块前缀或下划线风格（不用随意命名）
- [ ] 结构体名加 `_st` 后缀，联合体加 `_un` 后缀
- [ ] 跨协议边界的结构体已加 `__attribute__((__packed__))`
- [ ] 函数命名清晰，无歧义缩写

### ? 调度器规则
- [ ] **无 `HAL_Delay` / `delay_ms` 等阻塞调用**（在中断或调度循环中绝对禁止）
- [ ] 无全局 `while(1)` 死等（应用状态机代替）
- [ ] 多步骤逻辑用 `static u8 step` + `switch-case` 实现
- [ ] 时间敏感操作在正确的调度频率循环中（时序敏感用100/200Hz，控制用50Hz）

### ? 协议发送规范
- [ ] 发送 **CMD帧（0xE0）前**检查了 `dt.wait_ck == 0`
- [ ] 目标地址使用正确：
  - 发CMD → `0xFF`（广播）
  - 读写IMU参数 → `0x60`
  - 回CK给上位机 → `0xAF`（`SWJ_ADDR`）
- [ ] SC/AC 校验循环覆盖 **LEN+4 个字节**（不是 `len-2`）
- [ ] 0xE0 CMD帧 **LEN固定为11**（CID + CMD[0]~CMD[9]）
- [ ] 结构体字段按**小端序**排列（低字节在前）

### ? 已知 Bug 主动检查
- [ ] 若引用四元数（0x04帧）：`ANO_DT_LX.c` 中需确认第二个 `else if` 判断的是 `0x04` 而非 `0x03`
- [ ] 若使用测距数据：`_general_dis_st.distance_cm` 应为 `u32`（非 `s32`），否则 `0xFFFFFFFF` 被读为 `-1`

### ? 内存安全
- [ ] **无 `malloc` / `free`**（项目禁止动态内存）
- [ ] 数组下标访问有边界保护
- [ ] 函数内无大型局部数组（可能导致栈溢出，改用 `static` 或全局变量）
- [ ] 字符串操作无缓冲区溢出风险

### ? 飞行模式约束
- [ ] B类CMD（起飞 CMD1=0x05 / 降落 CMD1=0x06）调用前已确认当前模式非模式0（姿态自稳）
- [ ] C类CMD（平移/旋转/航点等）调用前已确认 `fc_sta.fc_mode_sta == 3`
- [ ] 发送 `0x41` 实时控制帧前已确认程控模式 `fc_sta.fc_mode_sta == 3`

### ? 代码可读性与可扩展性
- [ ] 状态机 `case` 注释清晰，说明每个状态的含义
- [ ] 无魔法数字（协议相关常量应有注释说明含义）
- [ ] 模块职责单一，无"大锅饭"函数
