# 凌霄协议通信调试

## 排查流程

### 步骤1：确认硬件层
- UART 波特率必须为 **500000** baud（凌霄IMU固定波特率）
- TX/RX 引脚是否对调（常见低级错误）
- UART 中断是否使能（检查 `McuConfig.h` 和 BSP 初始化）
- 若问题表现为 `0x0D` 电压消失、`0x0E` 外接状态无效、光流/激光/通用速度无数据或出现“运动解算失效复位”，先查硬件接线，不要先改协议代码：UART2 串口桥是否反灌/电平异常，`UART5/USART5` 是否误接了外部 USB-TTL `TX`。
- `UART5/USART5` 是 STM32 ↔ 凌霄IMU主通信口。树莓派只读 IMU 遥测时只能 `飞控USART5 RX → USB-TTL RX` 加 GND 旁路监听，USB-TTL `TX/VCC` 和飞控 `USART5 TX` 不接；树莓派主动发位置/目标只能走 UART2 `0xF5`。

### 步骤2：确认帧解析状态机
检查 `ANO_DT_LX_Data_Receive_Prepare()` 的状态机逻辑：
- 状态0：是否能识别 `0xAA` 帧头
- 状态1：目标地址过滤是否正确（允许 `0x61` 本机 或 `0xFF` 广播，两者都要处理）
- 状态3：LEN 是否有越界保护（应检查 `< 250`）

### 步骤3：校验计算核查
手动验证一帧数据的 SC/AC——**常见错误**是循环次数写错：

```c
/* ? 正确（覆盖 LEN+4 个字节：帧头+地址+ID+LEN+DATA）*/
for (i = 0; i < (data_buf[3] + 4); i++) {
    SC += data_buf[i];
    AC += SC;
}

/* ? 错误（老版本写法）*/
for (i = 0; i < len - 2; i++) { ... }
```

### 步骤4：检查已知源码 Bug
- **`ANO_DT_LX.c` 四元数Bug**：两个连续 `else if` 都判断 `*(data+2) == 0x03`，第二个应为 `0x04`。如果需要四元数数据（`0x04`帧）必须修复此处。
- **`LX_FC_EXT_Sensor.h` 测距类型**：`_general_dis_st.distance_cm` 若为 `s32`，收到 `0xFFFFFFFF` 时值变为 `-1`，应改为 `u32`。

### 步骤5：CMD 无响应排查
1. 确认 `dt.wait_ck == 0` 后再发送（否则CMD被丢弃）
2. 检查当前飞行模式是否满足CMD类别要求：
   - A类（解锁/上锁/悬停）：任意模式
   - B类（起飞/降落）：模式1/2/3，**不能在模式0使用**
   - C类（平移/旋转/航点）：**必须模式3（程控）**
3. 确认发送的 CID/CMD0/CMD1 值与 `LX_FC_Fun.c` 源码一致（源码可能基于早期协议版本）

### 步骤6：定位具体帧是否到达
在 `ANO_DT_LX_Data_Receive_Anl()` 中对目标帧ID加条件断点或 LED 闪烁指示，确认该帧是否通过了校验并进入解析阶段。

### 步骤7：数据单位核查
常见单位混淆：
| 数据 | 单位 | 换算 |
|------|------|------|
| 姿态角 | 0.01度 | 值3500 = 35.00度 |
| 速度 | cm/s | 值100 = 1m/s |
| 高度/位移 | cm | — |
| 电压 | 10mV | 值1250 = 12.50V |
| 四元数 | ×10000 | 值10000 = 1.0 |
