# Codex Git 与备份安全规则（最高优先级）

更新时间：2026-07-19

本文件记录用户对 Git 历史、项目历史回滚、进度记忆和代码备份的硬约束。后续所有开发、调试、修复和文档维护都必须遵守。

## 1. 回滚权限边界

- Codex 永远不能擅自执行 Git 历史或项目历史回滚。
- 任何 `git reset`、`git checkout -- <file>`、`git restore`、`git revert`、`git clean`、强制切分支、回退提交、删除历史、覆盖工作区的操作，都必须由用户亲手执行。
- 即使用户说“回滚”“恢复旧版本”“撤回到某次提交”，Codex 也只能：
  1. 解释风险和影响范围。
  2. 给出建议命令或操作步骤。
  3. 等用户亲自执行后，再基于新的工作区继续分析。
- Codex 如果需要撤销自己刚做错的普通代码改动，必须优先采用“前进式修复”（再次编辑成正确状态），不能用 Git 回滚命令。
- 发现用户已经手动回滚或工作区突然变化时，不要恢复被回滚内容；先重新读取当前文件状态，再根据用户最新目标继续。

## 2. 实时进度与记忆更新

- 完成可验证功能、修复缺陷、确认根因、纠正旧记忆、形成新硬约束后，必须立即更新 `memories/repo/dev-log.md`。
- 长周期 GUI、路径可视化、飞控任务序列、协议扩展等阶段性工作，必须同步更新对应 `project_docs/`、计划文件或 README，不能只在对话里说明。
- 记录必须包含：问题/目标、根因或依据、解决方案、验证结果、下次避免方法。
- 如果代码修改后尚未由用户实机验证，必须在记录里标明“已离线验证/待实机确认”，不能把未实飞结果写成已完成。

## 3. 必要时备份开发代码

以下情况属于“必要时”，修改前应先做轻量备份：

- 大范围重构或多文件联动修改。
- 飞控安全逻辑、协议收发、传感器接入、状态机、PID/任务序列等高风险修改。
- GUI 大阶段、路径可视化、数据记录器等长周期功能修改。
- 工作区已有用户未提交改动，且本次修改会接触同一文件。
- 用户明确担心误回滚、代码丢失或希望保留当前阶段成果。

推荐备份方式：

- 优先保存源码差异补丁和关键文件副本到 `记忆迁移/codex记忆迁移/backups/YYYYMMDD-HHMMSS/`。
- 备份内容应包含 `README.md`，说明备份原因、涉及文件、当前目标和验证状态。
- 只备份源码、文档、配置和必要补丁；不要备份 `.venv`、`build-gcc/`、日志缓存、截图缓存等大体积生成物。
- 备份不能替代 dev-log；备份后仍要在 `dev-log.md` 记录关键进度。

## 4. 工作区卫生

- 开始修改前查看相关文件状态，避免覆盖用户改动。
- 不删除用户未确认的文件、备份、日志、数据采集文件或构建产物。
- 不把临时实验、下载资料、生成文件混入正式源码路径；需要保留的资料放入明确的 `project_docs/` 或 `backups/`。
- 不主动提交、推送、改写 Git 历史；如果用户需要提交或上传，先说明当前改动范围和未验证事项。
