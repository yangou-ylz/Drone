## 2. 用户实机验收步骤

插上 DAP 和 STM32F407 板子后，在终端执行：

```bash
cd /home/ubuntu22/stm32/ANO_LX_FC
./scripts/check-dap.sh
```

验收点：

- [ ] `lsusb` 能看到 DAP/CMSIS-DAP/debug probe 相关设备。

然后执行只连接、不烧录的探测：

```bash
./scripts/probe-dap.sh
```

验收点：

- [ ] OpenOCD 能识别 CMSIS-DAP。
- [ ] OpenOCD 能识别 STM32F407 target。
- [ ] 没有 USB 权限错误。
- [ ] 没有 SWD 连接失败。

如果默认探测失败，执行低速无 NRST 备用探测：

```bash
./scripts/probe-dap-low-speed.sh
```

验收点：

- [ ] 低速 `adapter speed 1000`、无 SRST 配置能连接目标。

确认能连接后执行烧录：

```bash
./scripts/flash-dap.sh
```

验收点：

- [ ] OpenOCD 完成 erase/program。
- [ ] OpenOCD 完成 verify。
- [ ] OpenOCD reset 后退出。
- [ ] 用户确认板子运行符合预期。

如果默认烧录失败，但低速探测成功，执行备用烧录：

```bash
./scripts/flash-dap-low-speed.sh
```

验收点：

- [ ] 低速无 NRST 配置完成 program + verify + reset。

## 3. 失败时固定排查顺序

如果任何一步失败，先保存诊断信息：

```bash
./scripts/diagnose-dap.sh
```

诊断日志位置：

```text
logs/dap-diagnostics-YYYYMMDD-HHMMSS.log
```

然后按顺序判断：

1. `check-dap.sh` 看不到 DAP：优先检查 USB 线、USB 口、DAP 供电和扩展坞。
2. 能看到 DAP 但 OpenOCD 权限错误：运行 `./scripts/suggest-udev-rule.sh` 生成规则建议；写系统 udev 规则前必须确认。
3. OpenOCD 能打开 DAP 但找不到 target：检查 SWDIO/SWCLK/GND/3V3/NRST 接线和板子供电。
4. 默认配置失败：运行低速无 NRST 探测和烧录脚本。
5. verify 失败：降低 SWD 速度，确认供电稳定，检查目标芯片是否读写保护。
