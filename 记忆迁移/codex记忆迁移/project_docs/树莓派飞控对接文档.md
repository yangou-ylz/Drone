# 树莓派 × STM32 飞控正式对接文档

**版本**：v1.2 · 2026-07-19
**对象**：树莓派侧开发人员 / 树莓派侧 AI 代码生成器
**飞控硬件**：凌霄飞控 = STM32F407 可编程主控 + 凌霄 IMU 闭源控制核心

> 本文档可以直接发给树莓派侧开发人员。请同时附上 `groundTest/ano_protocol.py`、`groundTest/send_f5.py`、`groundTest/test_f5_frame.py`，这样对方可以直接复用构帧、校验和日志监听逻辑。

## 1. 系统边界

```
树莓派
  ├─ N10P/SLAM：输出当前定位
  ├─ K230/视觉：输出目标相对偏移
  ├─ 坐标转换：转成飞控坐标系，单位 cm
  └─ 串口发送：0xF5 位置/目标帧，建议 20~50Hz

STM32F407
  ├─ UART2 接收 0xF5
  ├─ 第一阶段：只解析、保存快照、输出 0xA0 日志
  └─ 后续阶段：在确认通信/坐标/失效保护后，再接 PID 和 0x41

凌霄 IMU
  └─ 闭源传感/融合/控制核心，不修改内部代码
```

分工：

| 模块 | 负责 | 不负责 |
|---|---|---|
| 树莓派 | SLAM、视觉、坐标转换、0xF5 打包发送、树莓派侧日志 | PID 控制、飞控决策 |
| STM32 | 解析 0xF5、日志、后续 PID 和速度指令组织 | SLAM/图像处理、修改 IMU 闭源算法 |
| 凌霄 IMU | 闭源速度环/姿态环/融合控制 | 树莓派应用逻辑 |

当前 STM32 阶段状态：

- `UART2` 已按 `PD5=TX / PD6=RX / 500000 / 8N1 / 无校验 / 无流控` 接入树莓派链路。
- `0xF5` 已进入 UART2 专用接收状态机，校验 `AA 61/FF F5 19`、31B 总长、SC/AC。
- 校验通过后已解析 `cur_x/y/z`、`tar_x/y/z`、`flags`，并通过 UART2 TX 回 `0xA0` 绿色 ACK。
- 树莓派侧已实测固定帧、X/Y/Z 方向帧、`SLAM_VALID/TARGET_VALID` flags 帧均能收到正确 ACK。
- 当前固件仍然 **只收、只解析、只回日志，不控飞**。
- 树莓派侧不能假设发送 `0xF5` 后飞机会运动；运动控制必须等后续阶段逐步打开。

协作调度方式：

- 本项目现在采用 **双端同步阶段闸门**，不是飞控侧或树莓派侧单线推进。
- 每一阶段由飞控侧先完成一个最小可验证改动并汇报当前进度。
- 随后明确树莓派侧必须执行的脚本、期望日志、失败时需要回传的材料。
- 树莓派侧完成并把日志/结果发回后，飞控侧再继续下一阶段。
- 未收到当前阶段树莓派侧通过结果前，不进入后续控制阶段，尤其不跳级接 PID、`0x41` 或实机运动输出。

## 2. 串口接线

### 2.1 第一阶段推荐：USB-TTL 接树莓派 USB 口

这是正式联调第一阶段推荐方案，调试最清楚，不需要先处理树莓派 GPIO 串口控制台/蓝牙占用问题。

| USB-TTL 模块 | 方向 | STM32F407 |
|---|---:|---|
| `TXD` | → | `PD6 / UART2_RX` |
| `RXD` | ← | `PD5 / UART2_TX` |
| `GND` | ↔ | `GND` |
| `VCC` | 不接 | 不接 STM32，除非另行确认供电方案 |

要求：

- USB-TTL 必须是 **3.3V TTL 电平**。
- 不要使用 RS232 电平模块。
- 如果 USB-TTL 有 `3.3V/5V` 跳帽，设置为 `3.3V`。
- 必须共地。
- 强烈建议接双向线：`TXD/RXD/GND` 都接上，这样树莓派能看到 STM32 的 `0xA0` ACK/日志。

树莓派侧串口设备：

- 优先使用稳定路径：`/dev/serial/by-id/...`
- 临时测试可用：`/dev/ttyUSB0`
- 串口参数：`500000 baud, 8N1, no parity, no flow control`

### 2.2 备选：树莓派 GPIO UART 直连

如果后续要取消 USB-TTL，可以改成 GPIO UART：

| 树莓派 | 方向 | STM32F407 |
|---|---:|---|
| `GPIO14 / TXD` | → | `PD6 / UART2_RX` |
| `GPIO15 / RXD` | ← | `PD5 / UART2_TX` |
| `GND` | ↔ | `GND` |

树莓派需要额外处理：

- 禁用串口控制台。
- 如使用硬件 UART，必要时禁用蓝牙占用。
- 设备名通常是 `/dev/serial0` 或 `/dev/ttyAMA0`。

## 3. 0xF5 帧格式

匿名协议基础格式：

```text
AA | DEST | CMD | LEN | DATA[LEN] | SC | AC
```

`0xF5` 自定义位置帧固定 31 字节：

| 偏移 | 字段 | 类型 | 说明 |
|---:|---|---|---|
| 0 | `HEAD` | u8 | 固定 `0xAA` |
| 1 | `DEST` | u8 | 固定 `0x61`，STM32 本机地址 |
| 2 | `CMD` | u8 | 固定 `0xF5` |
| 3 | `LEN` | u8 | 固定 `0x19`，DATA 长度 25 |
| 4~7 | `cur_x` | s32 LE | 当前 X，cm |
| 8~11 | `cur_y` | s32 LE | 当前 Y，cm |
| 12~15 | `cur_z` | s32 LE | 当前 Z，cm |
| 16~19 | `tar_x` | s32 LE | 目标 X，cm |
| 20~23 | `tar_y` | s32 LE | 目标 Y，cm |
| 24~27 | `tar_z` | s32 LE | 目标 Z，cm |
| 28 | `flags` | u8 | 状态标志 |
| 29 | `SC` | u8 | 和校验 |
| 30 | `AC` | u8 | 附加校验 |

`flags`：

| bit | 名称 | 含义 |
|---:|---|---|
| 0 | `SLAM_VALID` | 1=SLAM 定位正常 |
| 1 | `TARGET_VALID` | 1=目标坐标有效 |
| 2 | `VISUAL_MODE` | 1=目标来自视觉/K230，0=固定航点 |
| 3~7 | 保留 | 必须填 0 |

无效值：

- 协议字节约定为 `0x80000000`。
- Python signed int 里必须写 `-2147483648`。
- 不要把 `0x80000000` 直接传给 `struct.pack("<i")`，否则会越界报错。

校验：

```python
sc = 0
ac = 0
for b in frame[:29]:
    sc = (sc + b) & 0xFF
    ac = (ac + sc) & 0xFF
frame[29] = sc
frame[30] = ac
```

黄金样例：

```text
cur=(0,0,80), tar=(100,0,80), flags=0x03

AA 61 F5 19 00 00 00 00 00 00 00 00 50 00 00 00 64 00 00 00 00 00 00 00 50 00 00 00 03 20 36
```

## 4. 坐标系

飞控要求树莓派发来的坐标已经转换到飞控坐标系：

```text
原点：任务启动/对齐时飞机所在位置
X：机头前方为正
Y：机体左侧为正
Z：向上为正
单位：cm
```

树莓派职责：

- 记录 SLAM 初始化时的世界坐标原点。
- 记录起始 yaw / 机头方向。
- 把 SLAM 世界坐标旋转/平移到飞控坐标系。
- 发给 STM32 前必须已经是 `X前、Y左、Z上、cm`。

调试时先只发固定值，不要一上来接真实 SLAM：

```text
cur=(0,0,0), tar=(100,0,0)  # 验证 +X 前
cur=(0,0,0), tar=(0,100,0)  # 验证 +Y 左
cur=(0,0,0), tar=(0,0,100)  # 验证 +Z 上
```

## 5. 树莓派侧建议实现

优先直接复用本仓库：

- `groundTest/ano_protocol.py`
- `groundTest/send_f5.py`
- `groundTest/test_f5_frame.py`

核心构帧函数逻辑：

```python
import struct

INVALID_S32 = -2147483648
FLAG_SLAM_VALID = 0x01
FLAG_TARGET_VALID = 0x02
FLAG_VISUAL_MODE = 0x04


def to_s32_cm(v):
    if v is None or (isinstance(v, float) and v != v):
        return INVALID_S32
    iv = int(round(v))
    if not (INVALID_S32 <= iv <= 2147483647):
        raise ValueError(f"out of s32 range: {v}")
    return iv


def build_f5_frame(cur_x, cur_y, cur_z, tar_x, tar_y, tar_z, flags):
    frame = bytearray(31)
    frame[0:4] = bytes([0xAA, 0x61, 0xF5, 0x19])
    struct.pack_into(
        "<iiiiiiB",
        frame,
        4,
        to_s32_cm(cur_x),
        to_s32_cm(cur_y),
        to_s32_cm(cur_z),
        to_s32_cm(tar_x),
        to_s32_cm(tar_y),
        to_s32_cm(tar_z),
        flags & 0xFF,
    )
    sc = 0
    ac = 0
    for b in frame[:29]:
        sc = (sc + b) & 0xFF
        ac = (ac + sc) & 0xFF
    frame[29] = sc
    frame[30] = ac
    return bytes(frame)
```

必须有日志：

- 同时打印到屏幕和文件。
- 文件建议使用 rotating log。
- 每次记录：串口设备名、波特率、TX计数、flags、cur/tar、收到的 STM32 `0xA0` 日志。
- 第一阶段看到 STM32 回传类似：

```text
[RX 0xA0 GREEN] F5 #12 f=03 c=0,0,80 t=100,0,80
```

## 6. 分阶段联调计划

执行原则：每个阶段必须“飞控侧完成并汇报 → 树莓派侧按指定命令验证 → 用户回传日志 → 再进入下一阶段”。不要一次性把后续控制目标全部做完。

### 阶段 0：文档和代码版本确认

目标：确认双方拿到的是同一版协议。

验收：

- 树莓派侧运行 `python3 groundTest/test_f5_frame.py`，输出 `OK`。
- 黄金 hex 与本文档一致。
- STM32 侧确认固件包含 `0xF5` 解析入口。

### 阶段 1：串口硬件链路

目标：只验证 USB-TTL 和双向串口。

做法：

- USB-TTL 插树莓派 USB。
- `TXD -> PD6`，`RXD <- PD5`，`GND <-> GND`。
- 树莓派确认 `/dev/serial/by-id/...` 或 `/dev/ttyUSB0`。

验收：

- 树莓派能打开串口。
- STM32 上电后树莓派脚本能持续监听，不报串口异常。

### 阶段 2：固定 0xF5 单帧

目标：确认 STM32 能收到合法 `0xF5`。

命令：

```bash
python3 groundTest/send_f5.py --port /dev/ttyUSB0 --cur 0,0,80 --tar 100,0,80
```

验收：

- 树莓派日志出现 `[TX #1]`。
- 树莓派收到 STM32 `0xA0`：
  - `F5 #... f=03 c=0,0,80 t=100,0,80`

### 阶段 3：固定坐标方向测试

目标：确认 X/Y/Z 方向不反。

命令：

```bash
python3 groundTest/send_f5.py --port /dev/ttyUSB0 --cur 0,0,0 --tar 100,0,0 --rate 10 --duration 5
python3 groundTest/send_f5.py --port /dev/ttyUSB0 --cur 0,0,0 --tar 0,100,0 --rate 10 --duration 5
python3 groundTest/send_f5.py --port /dev/ttyUSB0 --cur 0,0,0 --tar 0,0,100 --rate 10 --duration 5
```

验收：

- STM32 日志能交替显示当前 `c=` 和目标 `t=`。
- 三个方向的数值和预期一致。
- 这一步仍然不解锁、不控飞。

### 阶段 4：失效状态测试

目标：验证 flags 不会被误解。

命令：

```bash
python3 groundTest/send_f5.py --port /dev/ttyUSB0 --cur 0,0,0 --tar 100,0,0 --slam-invalid
python3 groundTest/send_f5.py --port /dev/ttyUSB0 --cur 0,0,0 --tar 100,0,0 --target-invalid
```

验收：

- STM32 能收到 `f=02` 或 `f=01` 等 flags 变化。
- 当前阶段只记录日志。
- 后续控制阶段必须把 `SLAM_VALID=0` 和超时视为安全停止条件。

### 阶段 5：接入 SLAM 当前坐标

目标：只接 `cur`，目标先等于当前位置。

规则：

- `tar = cur`
- 第一轮真实 SLAM 测试建议 `TARGET_VALID=0`，即 flags 只置 `SLAM_VALID`；也可以 `tar=cur` 作为双保险。
- SLAM 未收敛、定位跳变或丢失时必须清 `SLAM_VALID=0`。
- 不允许触发实际运动。

验收：

- 坐标连续。
- 单位是 cm。
- 静止时噪声可接受。
- 起点附近不会突然出现十几米偏移。
- STM32 ACK 中 `c=` 能连续反映真实 SLAM 当前位置；`t=` 等于 `c=` 或目标无效。

### 阶段 6：目标坐标日志干运行

目标：树莓派发真实 `cur/tar`，STM32 只计算/打印误差，不接 0x41。

验收：

- `tar-cur` 方向正确。
- 视觉丢失时 `tar=cur` 或 `TARGET_VALID=0`。
- SLAM 丢失时 `SLAM_VALID=0`。

### 阶段 7：闭环控制干运行

目标：STM32 内部计算 PID 输出，但不送入飞行输出。

验收：

- 目标在 +X，输出方向应为 +X。
- 目标在 -X，输出方向应为 -X。
- Y/Z 同理。
- 有限幅、有超时、有日志。

### 阶段 8：低速单轴实机

目标：每次只打开一个轴，低速、短距离、带保护。

顺序：

1. X 轴 20cm
2. Y 轴 20cm
3. Z 轴 20cm

验收：

- 方向正确。
- 停止可靠。
- 不明显反向、不发散。

### 阶段 9：XY/Z 联动和视觉任务

目标：单轴稳定后逐步打开组合任务。

顺序：

1. XY 联动
2. 加 Z
3. 固定航点
4. 视觉目标
5. 视觉丢失/SLAM丢失/串口拔掉保护

## 7. 故障排查顺序

固定按这个顺序查，不要直接猜控制算法：

1. 树莓派日志：是否按 500000 打开正确串口。
2. 树莓派 TX：是否发出 31B `AA 61 F5 19 ...`。
3. STM32 ACK：是否收到 `F5 #...` 的 `0xA0`。
4. flags：`SLAM_VALID` / `TARGET_VALID` 是否符合当前状态。
5. 坐标：是否已经转成 `X前、Y左、Z上、cm`。
6. 后续控制阶段再查 PID、限幅、0x41 和飞行模式。
