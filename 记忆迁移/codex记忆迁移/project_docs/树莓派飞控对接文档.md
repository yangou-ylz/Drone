**版本**：v1.0 · 2026-07-12  
**适用对象**：负责树莓派侧开发的队友  
**飞控**：STM32F407 + 凌霄IMU（室内四旋翼）

## 一、系统架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                         树莓派                               │
│                                                             │
│   [N10P 激光雷达]              [K230 视觉模块]              │
│    SLAM 定位算法                目标检测（神经网络）          │
│    → 飞机当前绝对坐标            → 目标相对飞机的偏移量       │
│      (cur_x, cur_y, cur_z)       (dx, dy, dz)               │
│              │                         │                    │
│              └──────────┬──────────────┘                    │
│                         ▼                                   │
│               数据融合 & 坐标计算                            │
│               → 当前位置 (cur_x, cur_y, cur_z)              │
│               → 目标位置 (tar_x, tar_y, tar_z)              │
│               → 状态标志 flags                               │
│                         │                                   │
│                    打包 0xF5 帧，50Hz                        │
└─────────────────────────┼───────────────────────────────────┘
                          │ UART 串口（500000 baud）
                          │ 31字节/帧
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                      STM32F407（飞控）                       │
│                                                             │
│   UART2（PD6=RX）接收数据                                   │
│   └→ 解析 0xF5 帧                                           │
│       cur = 当前位置观测量                                   │
│       tar = PID 控制目标                                     │
│       vel_x = PID(tar_x, cur_x)                             │
│       vel_y = PID(tar_y, cur_y)                             │
│       vel_z = PID(tar_z, cur_z)                             │
│           │                                                 │
│           ▼ 0x41 实时控制帧，50Hz                           │
│   凌霄 IMU（速度环 + 姿态环，闭源）                         │
│   └→ 驱动电机，飞机运动                                     │
└─────────────────────────────────────────────────────────────┘
```

### 分工说明

| 模块 | 职责 | 不负责 |
|------|------|--------|
| **树莓派** | SLAM定位、视觉检测、坐标融合、打包发送 | PID控制、飞控决策 |
| **STM32** | 接收数据、PID位置控制、发速度指令 | 传感器融合、图像处理 |
| **凌霄IMU** | 速度环、姿态环（闭源，自动完成） | — |

> **比赛规则符合性**：飞控决策完全在 STM32 上运行，树莓派只做数据提供，符合"不允许使用载机计算机进行飞控"的规定。

## 二、串口硬件连接

### 接线

| 树莓派引脚 | 方向 | STM32 引脚 |
|-----------|------|-----------|
| GPIO14（TXD）| → | PD6（UART2 RX） |
| GPIO15（RXD）| ← | PD5（UART2 TX，可不接） |
| GND | ↔ | GND（**必须共地**） |

> **电平说明**：树莓派 GPIO 是 3.3V，STM32 PD6 是 5V 容忍引脚，**可直连，无需电平转换**。

### 串口参数

| 参数 | 值 |
|------|---|
| 波特率 | **500000 bps** |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 流控 | 无 |

## 三、通信帧格式（0xF5 自定义位置帧）

### 帧结构（共 31 字节）

```
偏移   字段         类型    说明
────────────────────────────────────────────────────────
[0]    帧头         u8     固定 0xAA
[1]    目标地址     u8     固定 0x61（STM32本机地址）
[2]    帧ID         u8     固定 0xF5（自定义帧）
[3]    数据长度     u8     固定 0x19（25字节）
[4~7]  cur_x        s32    飞机当前X坐标，单位cm，小端序
[8~11] cur_y        s32    飞机当前Y坐标，单位cm，小端序
[12~15]cur_z        s32    飞机当前Z坐标，单位cm，小端序
[16~19]tar_x        s32    目标X坐标，单位cm，小端序
[20~23]tar_y        s32    目标Y坐标，单位cm，小端序
[24~27]tar_z        s32    目标Z坐标，单位cm，小端序
[28]   flags        u8     状态标志（见下方定义）
[29]   SC           u8     和校验
[30]   AC           u8     附加校验
────────────────────────────────────────────────────────
```

### flags 字节定义

```
bit0 (0x01): SLAM_VALID   — 1=SLAM定位正常，0=SLAM丢失或初始化中
bit1 (0x02): TARGET_VALID — 1=目标坐标有效，0=无任务/视觉丢失
bit2 (0x04): VISUAL_MODE  — 1=目标来自K230视觉，0=来自固定航点
bit3~7:      预留，填0
```

### 无效值约定

某轴数据不可用时，填充 `0x80000000`（s32最小值，约-2147483648）。  
飞控收到无效值后将停止该轴控制并悬停。

### 校验算法（SC/AC）

```
校验范围：从帧头[0]到flags[28]，共29字节（不含SC/AC本身）

SC = 0, AC = 0
for i in range(0, 29):
    SC = (SC + frame[i]) & 0xFF
    AC = (AC + SC) & 0xFF
frame[29] = SC
frame[30] = AC
```

## 四、坐标系约定（重要，必须对齐）

### 飞控坐标系

```
原点：任务启动时飞机所在位置（飞控 step=1 初始化时记录）
X 轴：机头朝向为正（向前 +X）
Y 轴：机体左侧为正（向左 +Y）
Z 轴：向上为正（升高 +Z）
单位：厘米（cm）
```

### 树莓派的处理职责

SLAM 输出的坐标系通常是固定世界坐标系，**树莓派必须在发送前完成坐标转换**，使发出的 `cur_x/y/z` 和 `tar_x/y/z` 符合上述飞控坐标系定义。

**建议做法**：飞机起飞时记录 SLAM 原点和当时的机头朝向角，计算旋转矩阵，之后每帧做一次坐标变换。

## 五、两种工作模式

### 模式A：航点导航模式

```
使用场景：飞到指定坐标、定点悬停、精确巡航

tree莓派逻辑：
  cur = SLAM输出的当前位置（坐标转换后）
  tar = 当前任务航点（事先规划或地面站下发）
  flags = 0x03（SLAM_VALID | TARGET_VALID）

飞控行为：
  PID驱动飞机从 cur 飞向 tar
  误差 = tar - cur → 速度指令 → 凌霄IMU
```

### 模式B：视觉伺服模式

```
使用场景：识别目标后靠近、扫描、对准

树莓派逻辑：
  cur = SLAM输出的当前位置
  tar = cur + K230输出的目标相对偏移量(dx, dy, dz)
       （目标相对飞机的距离，叠加到当前位置得到目标绝对坐标）
  flags = 0x07（SLAM_VALID | TARGET_VALID | VISUAL_MODE）

视觉丢失时：
  tar = cur  （目标等于当前位置，误差=0，飞机自然悬停）
  flags = 0x03（清除 VISUAL_MODE 位）

飞控行为：
  与模式A完全相同，无感知视觉是否介入
```

> **设计精髓**：模式切换完全在树莓派侧处理，飞控侧只看到"(当前位置, 目标位置)"这一对数值，无需区分数据来源，代码逻辑最简单。

## 六、Python 发送代码

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
树莓派端：向 STM32 飞控发送 0xF5 位置帧
"""
import struct
import serial
import time

INVALID_S32 = 0x80000000   # 某轴无效时填充此值

# flags 位定义
FLAG_SLAM_VALID   = 0x01
FLAG_TARGET_VALID = 0x02
FLAG_VISUAL_MODE  = 0x04


def build_f5_frame(cur_x, cur_y, cur_z,
                   tar_x, tar_y, tar_z,
                   flags: int) -> bytes:
    """
    构造 0xF5 自定义位置帧（31字节）

    参数：
        cur_x/y/z  飞机当前位置（cm），None 或 float('nan') 表示无效
        tar_x/y/z  目标位置（cm），同上
        flags      状态标志字节
    返回：
        31字节 bytes
    """
    def to_s32_bytes(v) -> int:
        if v is None or (isinstance(v, float) and v != v):
            return INVALID_S32
        return int(round(v)) & 0xFFFFFFFF

    frame = bytearray(31)
    frame[0] = 0xAA
    frame[1] = 0x61   # 目标地址：STM32
    frame[2] = 0xF5   # 帧ID
    frame[3] = 0x19   # 数据长度 = 25

    # 打包6个 s32（小端序）
    struct.pack_into('<iiiiii', frame, 4,
                     to_s32_bytes(cur_x),
                     to_s32_bytes(cur_y),
                     to_s32_bytes(cur_z),
                     to_s32_bytes(tar_x),
                     to_s32_bytes(tar_y),
                     to_s32_bytes(tar_z))
    frame[28] = flags & 0xFF

    # 计算校验（覆盖 [0]~[28] 共29字节）
    sc, ac = 0, 0
    for b in frame[:29]:
        sc = (sc + b) & 0xFF
        ac = (ac + sc) & 0xFF
    frame[29] = sc
    frame[30] = ac

    return bytes(frame)


class FcLink:
    """与飞控的串口通信管理"""

    def __init__(self, port='/dev/ttyAMA0', baudrate=500000):
        self.ser = serial.Serial(port, baudrate=baudrate, timeout=0.1)
        print(f"[FcLink] 串口已打开: {port}, {baudrate} baud")

    def send_pos(self, cur_x, cur_y, cur_z,
                 tar_x, tar_y, tar_z, flags):
        frame = build_f5_frame(cur_x, cur_y, cur_z,
                               tar_x, tar_y, tar_z, flags)
        self.ser.write(frame)

    def close(self):
        self.ser.close()


# ─────────────────────── 示例主程序 ───────────────────────

def main():
    fc = FcLink(port='/dev/ttyAMA0')

    # 模拟变量（替换为真实SLAM/K230接口）
    visual_task_active = False

    try:
        while True:
            t = time.monotonic()
            flags = 0

            # ── 获取SLAM当前位置 ──────────────────────────
            # TODO: 替换为 lidar_slam.get_position()
            slam_ok = True
            cur_x, cur_y, cur_z = 0.0, 0.0, 80.0   # 示例值
            if slam_ok:
                flags |= FLAG_SLAM_VALID

            # ── 计算目标位置 ──────────────────────────────
            if visual_task_active:
                # K230视觉模式
                # TODO: 替换为 k230.get_detection()
                det_ok = True
                dx, dy, dz = -20.0, 5.0, 0.0   # 示例：目标在前方20cm

                if det_ok and slam_ok:
                    tar_x = cur_x + dx
                    tar_y = cur_y + dy
                    tar_z = cur_z + dz
                    flags |= FLAG_TARGET_VALID | FLAG_VISUAL_MODE
                else:
                    # 视觉丢失：原地悬停
                    tar_x, tar_y, tar_z = cur_x, cur_y, cur_z
                    flags |= FLAG_TARGET_VALID
            else:
                # 航点模式：发送固定目标
                tar_x, tar_y, tar_z = 100.0, 0.0, 80.0   # 示例：前方100cm
                flags |= FLAG_TARGET_VALID

            # ── 发送 ─────────────────────────────────────
            fc.send_pos(cur_x, cur_y, cur_z,
                        tar_x, tar_y, tar_z, flags)

            # 50Hz
            elapsed = time.monotonic() - t
            sleep_time = max(0, 0.02 - elapsed)
            time.sleep(sleep_time)

    except KeyboardInterrupt:
        fc.close()
        print("[FcLink] 已关闭")


if __name__ == '__main__':
    main()
```

## 八、飞控侧的处理逻辑（供参考）

> 此部分由飞控侧开发，列出以便理解整体流程。

**超时保护**：飞控若 200ms 内未收到新帧，视为树莓派断联，立即停止 PID 输出并悬停。

**flags 处理**：
- `SLAM_VALID = 0`：停止任务，打印红色 LOG
- `TARGET_VALID = 0`：目标无效，保持悬停
- 两者均为1：正常 PID 控制

**PID 输入**：
```c
// 相对起飞点的误差
obs_x = cur_x - ref_x_at_start;   // 当前位置（相对起飞点）
obs_y = cur_y - ref_y_at_start;
obs_z = cur_z - ref_z_at_start;

goal_x = tar_x - ref_x_at_start;  // 目标（相对起飞点）
goal_y = tar_y - ref_y_at_start;
goal_z = tar_z - ref_z_at_start;

// PID：setpoint=goal, measurement=obs
vel_x = Pid_Update(&pid_x, goal_x, obs_x, 0.02f);
vel_y = Pid_Update(&pid_y, goal_y, obs_y, 0.02f);
vel_z = Pid_Update(&pid_z, goal_z, obs_z, 0.02f);
```

## 九、联调步骤

### 第一步：验证串口通信（不开飞机）

树莓派发固定帧（cur=0, tar=0, flags=0x03），飞控侧打开地面站监听 `0xA0` LOG，确认收到"RPi frame OK"回显。

### 第二步：验证坐标系（不解锁）

树莓派发 `tar_x` 从0线性增大（0→100cm），观察飞控 LOG 中 `obs_x` 和 `goal_x` 是否正确跟随变化。

### 第三步：绳子保护实飞

飞机绑好安全绳，验证XY方向的PID响应，调整 KP/KD。

### 第四步：切换视觉模式

激活 K230 检测，验证视觉模式下飞机能靠近识别目标，验证视觉丢失时飞机悬停。
