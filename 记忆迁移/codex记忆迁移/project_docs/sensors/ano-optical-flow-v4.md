## 核心原理

- 匿名光流 V4.0 是面向无人机低空悬停的速度传感器；V4 相比旧版提升光流识别率，改进 INS 融合算法，并完善状态和指令输出。
- 模块本体集成光流传感器和惯性传感器，并可外接高度传感器。光流单独使用会把镜头看到的地面纹理移动与机体姿态旋转耦合在一起，不能直接得到稳定悬停所需的真实水平速度。
- 正确工作链路是：地面纹理移动 + 加速度 + 角速度 + 对地高度融合，得到解耦/融合后的地面速度。不要把原始像素光流当成最终速度直接闭环。
- 光流不是绝对定位传感器，本质输出水平速度；长时间积分会有误差累积。官方也明确说明积分漂移属于正常现象。

## 安装和使用要点

- 模块安装在飞行器底部，尽量靠近飞行器中心；镜头朝下水平安装。
- 激光测距模块应距离地面 10 cm 以上，否则高度数据无效会导致光流数据无效。北醒 TF-mini(s) 这类激光模块 10 cm 内有测距死区。
- 不建议用扎带硬固定；因为模块内部有惯性测量单元，建议泡沫海绵双面胶或减震板降低振动影响。
- 串口 4P 接线时 VCC 必须为 5V；TX 接对侧 RX，线序错误有烧坏模块风险。
- 使用串口 4P 线连接飞控对应串口与光流模块 FC 接口；测距传感器接光流模块 ALT 接口。
- 模块 USB 连接配套匿名上位机，连接方式为 HID；建议使用购买光流模块时资料包中的上位机版本，版本不匹配可能配置失败。
- 串口配置为 8N1、无流控，默认波特率 500k；官方建议高于 500000，或者关闭不需要的输出、降低输出频率，避免串口阻塞。

## 输出数据理解

### 0x51 光流帧

- MODE 0：原始光流数据。`DX_0/DY_0` 是像素移动速度，单位像素/20ms；可用相对高度做粗略换算，但没有去除旋转耦合。
- MODE 1：协议表称“融合的光流数据”，物理意义说明称“解耦后的光流 DX1/DY1”。`DX_1/DY_1` 直接为地面速度，单位 cm/s；官方说明噪声较大，只适合做速度观测。本组数据仅在高度传感器有效、陀螺仪无异常时有效。
- MODE 2：惯导融合光流数据。`DX_2/DY_2` 为融合地面速度，噪声小但有零偏，适合速度环控制，积分会漂移；`DX_FIX/DY_FIX` 是积分修正后的速度，噪声稍大但积分后偏移小，更适合做积分计算；`INTEG_X/INTEG_Y` 是单纯速度积分，仅供参考，范围循环。
- `QUALITY` 是 0~255 的光流质量参考值，越大质量越好，但不能单独替代 STATE 和高度/陀螺有效性判断。

### 0x34 测距帧

- 匿名光流 V4 Wiki 中，模块输出的 0x34 定义为：`DIRECTION=0` 向下、`ANGLE=0` 恒定、`DIST` 为 cm，`0xFFFFFFFF` 无效。
- 注意：凌霄《匿名通信协议 V7》里的通用测距 0x34 定义与光流 Wiki 页面存在语义差异。向凌霄 IMU 转发高度时必须按“接收方 IMU 期望的通用测距协议”确认字段，不能盲目照搬光流模块自己的 0x34 字段解释。

## 当前工程对应关系

- `DriversBsp/Drv_AnoOf.c` 解析光流 0x51：
  - MODE 0 填 `of0_*`，不触发 0x33 上报。
  - MODE 1 填 `of1_dx/of1_dy/of1_sta`，并递增 `ano_of.of_update_cnt`。
  - MODE 2 填 `of2_dx/of2_dy/of2_dx_fix/of2_dy_fix/intergral_*`，但当前不用于 0x33 转发。
  - 0x34 高度帧填 `ano_of.of_alt_cm`，并递增 `alt_update_cnt`。
- `DriversBsp/Drv_AnoOf.c::AnoOF_Check_State()` 要求速度数据和高度数据都在 500ms 内持续更新，才置 `ano_of.work_sta=1`。
- `FcSrc/LX_FC_EXT_Sensor.c::General_Velocity_Data_Handle()` 当前只把 MODE 1 的 `of1_dx/of1_dy` 打包成 0x33 通用速度；若 `of1_sta` 或 `work_sta` 不满足，则把 X/Y 速度发为 `0x8000` 无效。
- 因此：当前工程的 0x33 代表“光流 MODE 1 速度观测”，不是 MODE 2 的 `DX_FIX/DY_FIX`，也不是光流模块自己的积分位置。

## 开发判断规则

- 2026-07-24 现场最终纠错：如果 GUI/官方上位机显示 `G_VEL`、`ALT`、`0x33`、`0x34` 等外部传感无数据，第一步不是改光流转发逻辑，而是先确认 `0x0D` 电池电压是否存在且稳定。实测中，异常 DAP/UART 复合串口模块接到树莓派 USB 后会导致飞控电压数据消失，随后光流/激光外部传感也消失；拔掉该模块后恢复。该现象会让之前的“IMU不采纳0x33/0x34”“光流转发格式错误”等分析变成坏硬件条件下的中间观察，不能当最终根因。
- 调定点和光流接入时，优先检查：光流 0x51 MODE 1 是否有效、0x34 高度是否持续、0x33 是否发给 IMU、IMU 回传 0x0E 的 `STA_G_VEL/STA_ALT_ADD` 是否为正常。
- 若要做位置积分，优先研究 MODE 2 的 `DX_FIX/DY_FIX` 或 IMU 回传的位置/速度语义；不要把 MODE 1 当作低漂移位移源。
- 看到“停下后速度反向/积分回弹”时，不要先怀疑光流硬件坏。需要区分：光流模块融合特性、凌霄 IMU 闭源融合/ZUPT 行为、GUI 积分策略、0x33/0x07/0x08 数据源归属。
- 修改 0x33/0x34 转发前，必须同时查：
