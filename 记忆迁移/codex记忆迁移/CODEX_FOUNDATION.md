# Codex 基础工作原理记忆（最高优先级）

更新时间：2026-07-24

本文件记录本项目最基础、最不可偏离的飞控工作原理。后续任何飞控、协议、传感器、GUI 数据解释和调试，都必须以这里的边界为前提。

## 1. 系统组成

本项目使用的是匿名凌霄飞控体系，核心由两部分组成：

- `STM32F407`：中央总控制器，负责复杂上层功能、任务组织、协议通信、遥控器/外部传感器数据打包、目标/速度/任务指令组织。本项目所有可修改代码都在 STM32 侧。
- `凌霄 IMU`：闭源控制/融合核心，作为传感器和内置算法模块存在。它输出匿名协议数据帧，内容不只包括惯性传感器数据，也包括飞控状态、命令状态、融合结果、电机 PWM 等底层关键数据。

## 2. 必须坚持的控制边界

- 凌霄 IMU 内部程序闭源，不能改、不能烧录、不能假设知道内部代码细节。
- STM32 侧不能直接改变凌霄 IMU 内部算法，只能按匿名协议把遥控器、外部传感器、任务目标、速度/位置指令等打包成数据帧发送给 IMU。
- IMU 如何融合、滤波、控制和输出，具体实现未知；只能通过官方手册、源码接口、串口抓包、实测数据来推断行为。
- 不允许把 STM32 代码误理解成姿态环、电机 PWM 闭环或凌霄内部算法的实现位置。

## 3. 数据链路理解

常见链路必须这样理解：

```text
遥控器 / 外部传感器 / 上位机 / 树莓派
        ↓
STM32F407：接收、解析、封装、组织任务和协议帧
        ↓  匿名协议帧
凌霄 IMU：闭源融合/控制/状态机/底层输出
        ↓  匿名协议帧
STM32 / 数传 / 上位机：接收数据帧并显示或再处理
```

关键提醒：

- 数传接的是凌霄 IMU 链路。不能认为改了 STM32 某段逻辑，就一定能直接改变数传输出的所有结果。
- 如果数传输出的某个状态、融合结果、电机 PWM 或底层数据没有变化，必须先判断该数据是否由 IMU 内部生成，而不是直接假设 STM32 逻辑能覆盖它。
- STM32 可以影响 IMU 的输入数据和命令帧；IMU 输出是否变化，取决于闭源算法是否接受、融合和响应这些输入。

## 3.1 电压遥测与外部传感器失效的前置排查

2026-07-24 实测确认：本项目中如果 `0x0D` 电池电压数据消失或变为异常，光流/激光高度/通用速度等外部传感显示也会随之消失，且 GUI/终端会出现：

```text
[A0 红] 运动解算失效复位
[A0 绿] 运动解算启动
```

工程推断：凌霄 IMU 的运动解算/外部传感融合对供电或电压遥测状态有安全依赖；当电压遥测失效时，IMU 会复位或停用运动解算，外部传感状态因此显示无数据。这是下游安全状态变化，不应先归因于光流模块坏、`0x33/0x34` 协议坏或 GUI 解析坏。

排查顺序必须固定：

1. 先看 `0x0D` 电池电压帧是否存在、raw 是否合理、帧计数是否增长。
2. 再看 `0x0E` 外接模块状态中的 `STA_G_VEL` 和 `STA_ALT_ADD`。
3. 如果插上树莓派 `UART2` USB-TTL / DAP-UART 模块后电压立即归零、拔掉立即恢复，优先判定为串口桥硬件/供电/地线/电平干扰。
4. 只有电压和外接模块状态稳定后，才继续排查光流 `0x51`、通用速度 `0x33`、通用测距 `0x34` 和 STM32 转发逻辑。

## 4. 手册优先

凡是涉及协议、地址、功能码、数据帧字段、外部传感器接入、模式响应、CMD 类别、0x41/0xE0/0xA0/0x32/0x33/0x34/0xF* 等内容，必须先查：

- `用户手册/匿名通信协议V7.pdf`
- `用户手册/匿名--凌霄--飞控手册.V1.07pdf.pdf`

手册、实测、源码和历史记忆冲突时：

1. 官方手册优先。
2. 手册不覆盖时，以当前源码和实测抓包为依据。
3. 必须把旧结论为何错、新结论依据是什么写入 `memories/repo/dev-log.md`。

## 5. 匿名系列外部传感器

本项目接入的一些匿名系列传感器（例如匿名光流 + 激光高度模块）与凌霄飞控属于同系列，协议适配性较高，但仍不能凭经验猜字段。

后续接入或调试匿名系列传感器时：

1. 先查本地 `用户手册/`、`project_docs/`、`memories/` 是否已有资料。
2. 本地没有权威资料时，可以上网查找官方/权威资料。
3. 获取到权威资料后，必须保存到本地知识库（优先放 `记忆迁移/codex记忆迁移/project_docs/sensors/` 或明确的传感器文档目录）。
4. 同步更新 `CODEX_MEMORY_INDEX.md`、相关 `project_docs/` 和 `dev-log.md`，防止后续误解传感器。

## 6. 后续开发禁止偏差

- 不允许说“改 STM32 某逻辑就直接改变 IMU/数传输出”而不分析数据链路。
- 不允许把凌霄 IMU 当作可修改源码的一部分。
- 不允许在不了解帧定义的情况下自行假设传感器打包规则。
- 不允许忽略 IMU 闭源算法的稳定性和不透明性，强行用 STM32 侧补丁解释所有底层输出。
- 所有上层功能设计都必须基于“STM32 组织输入帧/任务，IMU 闭源处理并输出帧”这个基本事实。
