# Codex 记忆维护规则

本文件规定 Codex 后续如何维护本迁移包，防止开发新阶段后遗忘旧约束。

## 必须更新 dev-log 的情况

出现以下任一情况，立即更新 `记忆迁移/codex记忆迁移/memories/repo/dev-log.md`：

- 解决了导致卡住的问题。
- 发现了非显而易见的项目约定。
- 用户纠正了 Codex 的错误判断。
- 修改了飞控安全相关逻辑。
- 完成了一个可验证功能。

记录格式：

```text
[日期] [问题] → [根因] → [解决方案] → [教训]
```

## 文档同步

- 改变编译、烧录、运行步骤时，更新对应 `project_docs/` 文档。
- 改变 GUI 使用方式时，更新 GUI README 或相关使用说明。
- 改变协议字段、帧格式、地址约定时，更新 `数据帧.md` 或协议说明，并注明官方手册依据。
- 新增或调试匿名系列外部传感器时，如果获取到官方/权威资料，保存到 `project_docs/sensors/` 或明确传感器文档目录，并更新 `CODEX_MEMORY_INDEX.md`。

## 记忆纠错

如果发现旧记忆错误：

1. 不要静默覆盖。
2. 在 dev-log 中记录旧结论、错误原因、新依据。
3. 再修改对应记忆文件。

## 新增 Codex 记忆

- 新增文件必须命名为 `CODEX_*.md` 或放在明确属于本项目的目录下。
- 新增内容必须只服务 `ANO_LX_FC` 飞控项目。
- 禁止混入其他项目经验、路径或规则。

## 清理规则

迁移包内不应出现：

- `.bak` 乱码或重复备份。
- 混合来源记忆。
- 其他项目路径、规则或经验。

清理后应运行关键词检查并确认无命中。
