## 帧格式

```
[0xAA] [目标地址] [ID/CMD] [数据长度N] [DATA字节0...N-1] [SC] [AC]
```

| 字节位置 | 字段 | 说明 |
|----------|------|------|
| 0 | 帧头 | 固定 `0xAA` |
| 1 | 目标地址 | 见地址表 |
| 2 | ID | 功能码 |
| 3 | 数据长度 | DATA区字节数（不含校验字节本身） |
| 4 ~ 4+N-1 | DATA | 有效数据，**小端模式**（低字节在前） |
| 4+N | SC | 和校验 |
| 4+N+1 | AC | 附加校验 |

## 硬件地址完整定义

| 地址码 | 定义 |
|--------|------|
| `0xFF` | 广播（所有设备都接收） |
| `0xAF` | 上位机（`SWJ_ADDR` in SysConfig.h） |
| `0x60` | **凌霄IMU**（闭源模块） |
| `0x61` | **凌霄飞控STM32板**（`HW_TYPE` in SysConfig.h） |
| `0x10` | 匿名数传 |
| `0x22` | 匿名光流 |
| `0x30` | 匿名UWB |
| `0x66` | 匿名控制台 |

> **常用规则**：
> - 向IMU/广播发命令：`dest = 0xFF`
> - 读写凌霄IMU参数：`dest = 0x60`
> - 向上位机回复CK：`dest = 0xAF`（`SWJ_ADDR`）

## 双向校验算法（SC/AC）

校验范围：**从帧头 `0xAA` 开始，直到DATA区结束**（不含SC/AC本身），共 LEN+4 个字节

```c
u8 SC = 0, AC = 0;
// data_buf[3] = LEN（数据长度），校验覆盖：帧头+地址+ID+LEN+DATA
for (u8 i = 0; i < (data_buf[3] + 4); i++) {
    SC += data_buf[i];   // 和校验：每字节累加，取低8位
    AC += SC;            // 附加校验：累加每次的SC，取低8位
}
// 发送时：data_buf[data_buf[3]+4] = SC, data_buf[data_buf[3]+5] = AC
// 接收校验：比较计算值与帧尾两字节
```

## 数据帧：STM32主动发送（STM32发送方）

| ID | 名称 | LEN | DATA格式 | 触发 |
|----|------|-----|----------|------|
| `0x0D` | 电池 | 4 | 同接收格式 | 定时100ms |
| `0x30` | GPS | 23 | FIX_STA(u8)+S_NUM(u8)+LNG(s32)×1e7+LAT(s32)×1e7+ALT_GPS(s32)+N/E/D_SPE(s16×3)+PDOP/SACC/VACC(u8×3) | 外部 |
| `0x32` | 通用位置 | 12 | POS_X/Y/Z(s32×3,cm，**0x80000000=无效**) | 外部 |
| `0x33` | 通用速度 | 6 | SPEED_X/Y/Z(s16×3,cm/s，**0x8000=无效**) | 外部 |
| `0x34` | 通用测距 | 7 | DIRECTION(u8)+ANGLE(u16,度)+DIST(**u32**,cm，**0xFFFFFFFF=无效**) | 外部 |
| `0x40` | 遥控器 | 20 | ROL/PIT/THR/YAW/AUX1~6(s16×10，1000-2000，0=失联) | 定时20ms |
| `0x41` | **实时控制** | 14 | 见下方详解 | 外部 |
| `0x51` | 光流 | 5~17 | 见下方MODE说明 | 外部 |
| `0xA0` | **LOG打印功能字符串** | N | DATA=`COLOR(u8)`+`STR(u8×(N-1))`，供下位机向上位机输出文本日志 | 外部 |
| `0xE0` | CMD命令 | 11 | CID(u8)+CMD0~9(u8×10) | 外部 |
| `0xE2` | 参数写入 | 6 | PAR_ID(u16)+PAR_VAL(s32) | 外部 |
| `0x00` | CK返回 | 3 | ID(u8)+SC(u8)+AC(u8) | 收到需回复帧后 |

> **0x32坐标系**：机头朝X轴正方向，机体左侧朝Y轴正方向
> **0x34方向**：DIRECTION=0水平（0=机头前方顺时针）；DIRECTION=1垂直（90=正上方）
> **0xA0官方用途**：匿名协议 PDF 第10页定义为“LOG打印功能--字符串”，用于向上位机发送文本信息；具体显示效果取决于上位机是否开启对应文本窗口。
> **0xA0字段细节**：`COLOR` 占 1 字节，`0=黑色`、`1=红色`、`2=绿色`；`STR` 为后续英文字符串 ASCII，不需要额外 `\0` 结束符，长度完全由 `LEN` 决定。

**0x51光流（三种MODE）**：
```
MODE=0（原始）: MODE(u8)+STATE(u8)+DX_0(s8,像素/20ms)+DY_0(s8)+QUALITY(u8) = 5字节
MODE=1（融合）: MODE(u8)+STATE(u8)+DX_1(s16,cm/s)+DY_1(s16,cm/s)+QUALITY(u8) = 7字节
MODE=2（惯导融合）: MODE(u8)+STATE(u8)+DX_2/DY_2(s16×2)+DX_FIX/DY_FIX(s16×2)+INTEG_X/Y(s16×2)+QUALITY(u8) = 17字节
```

## 实时控制帧（0x41）详解

```c
typedef struct {
    s16 rol;        // 期望滚转角（×100，0.01度，±90度）
    s16 pit;        // 期望俯仰角（×100，0.01度）
    s16 thr;        // 期望油门（0.1%，0-1000 对应 0%-100%）
    s16 yaw_dps;    // 期望偏航角速度（度/秒，±200°/s）
    s16 vel_x;      // 期望头向速度（cm/s，前飞为正）
    s16 vel_y;      // 期望左向速度（cm/s，左移为正）
    s16 vel_z;      // 期望天向速度（cm/s，上升为正）
} __attribute__((__packed__)) _rt_tar_st;
```

**各字段按飞行模式的有效性**（1=飞控响应，0=忽略）：

| 字段 | 模式0(姿态) | 模式1摇杆中位 | 模式1摇杆非中位 | 模式2(定点) | 模式3(程控) |
|------|:-----------:|:-------------:|:---------------:|:-----------:|:-----------:|
| rol | 1 | 1 | 0 | 0 | 0 |
| pit | 1 | 1 | 0 | 0 | 0 |
| thr | 1 | 0 | 0 | 0 | 0 |
| yaw_dps | 1 | 1 | 1 | 0 | 0 |
| vel_x | 0 | 0 | 1 | 0 | 0 |
| vel_y | 0 | 0 | 1 | 0 | 0 |
| vel_z | 0 | 1 | 1 | 0 | 0 |

> 程控模式3下，飞控完全由指令驱动，所有字段均为飞控自动控制参考值（飞控内部使用）。
> 定点模式2下，摇杆前4通道任意一个不在中位（PIT/ROL死区±40，THR/YAW死区±80），优先响应摇杆。

## CMD命令帧（0xE0）格式

```
0xAA | 0xFF | 0xE0 | 0x0B | CID(1字节) + CMD0~CMD9(10字节) | SC | AC
```
LEN固定为 **11**（CID=1字节 + CMD[0]~CMD[9]=10字节）。飞控收到后必须返回0x00校验帧。

### CMD发送规范（必须遵守）

```c
// 发送CMD前，必须检查当前没有待确认的CMD
if (dt.wait_ck == 0) {
    dt.cmd_send.CID = 0x10;      // 控制指令CID固定0x10
    dt.cmd_send.CMD[0] = 0x00;
    dt.cmd_send.CMD[1] = 0x01;   // 示例：解锁
    CMD_Send(0xFF, &dt.cmd_send);
    return 1;
} else {
    return 0;  // 等待上一个CMD的CK确认，不能发新CMD
}
```

### wait_ck 机制
- 发送CMD后，`dt.wait_ck` 置为非0（超时倒计时）
- 收到正确CK返回帧（ID=0x00）后，`dt.wait_ck` 清零
- 每个调度周期自减，超时自动清零（防死锁）
- **严禁**在 `dt.wait_ck != 0` 时发送新CMD

## 参数读写帧

### E1：参数读取请求
```
0xAA | 目标设备地址 | 0xE1 | 0x02 | PAR_ID低(u8)+PAR_ID高(u8) | SC | AC
```
读凌霄IMU参数时目标地址为 `0x60`。

### E2：参数写入 / 参数读取返回
```
0xAA | 目标设备地址 | 0xE2 | 0x06 | PAR_ID(u16)+PAR_VAL(s32) | SC | AC
```
写参数时目标地址为设备地址（如`0x60`）；下位机对上位机的读返回时目标地址为`0xAF`。
**飞控收到本帧需返回0x00校验帧。**

## 接收帧解析流程

接收入口：`ANO_DT_LX_Data_Receive_Prepare(u8 data)` — 每收到一个字节调用（UART中断中）

```
状态0 → 等待0xAA帧头
状态1 → 验证目标地址（0x61本机 或 0xFF广播）
状态2 → 接收ID字节
状态3 → 接收LEN字节（必须<250，防越界）
状态4 → 接收LEN个DATA字节
状态5 → 接收SC字节
状态6 → 接收AC字节 → 调用 ANO_DT_LX_Data_Receive_Anl() 完整解析
任何异常 → 状态归0，丢弃当前帧
```

## 已知源码BUG

1. **`ANO_DT_LX.c` 四元数帧解析错误**：两个 `else if` 都判断 `*(data+2)==0x03`，第二个应为 `0x04`，导致四元数永远不被解析。使用四元数时必须修复。

2. **`LX_FC_EXT_Sensor.h` 测距类型错误**：`_general_dis_st.distance_cm` 定义为 `s32`，但协议规定为 `u32`（0xFFFFFFFF=无效），收到无效值时s32会解读为-1，应改为 `u32`。

## 常见错误

1. **忘记检查 `dt.wait_ck`**：连续发送CMD导致校验混乱
2. **目标地址写错**：发命令用`0xFF`，读IMU参数用`0x60`，回CK用`0xAF`
3. **结构体未加`__packed__`**：字节对齐导致数据解析乱码
4. **CMD类别限制忽略**：B类指令在姿态模式失效，C类指令必须模式3才有效
5. **数据单位混淆**：角度×100（0.01度），速度cm/s，高度cm，电压×100（10mV），四元数×10000
6. **E0帧LEN=11**（CID+CMD0~CMD9），不要发送长度不符的命令帧
